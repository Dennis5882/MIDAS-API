# WallHelper 기획문서

> 영상(`docs/plugin_cases/videos/06_WallHelper.mp4`, 약 30fps, 1920×1080, 약 97초)을 5초 간격으로
> 프레임 캡처(총 20장) 후 프레임별 육안 분석 + 영상 내 자막(내레이션 캡션)을 근거로 작성. 영상은
> "1구간·2구간·3구간" 3단계 실습 형식으로 구성되어 있으며, 원문 아티클(`docs/plugin_cases/
> articles/06_WallHelper.md`)에는 "벽체 검토" 기능 1건만 소개되어 있지만 실제 화면에는 벽체
> 분할·벽체 정리·벽체 병합 3개 버튼이 노출됨 — 원문 소개 문구("분할하고 정리·병합하며 자동
> 수정")와 화면 UI가 일치함을 확인.

## 1. 개요

**WallHelper**는 GEN NX의 사각형 벽체(Wall)를 하나의 화면에서 기준 길이로 분할(Split)하고,
주변 노드 격자에 맞춰 정리(Cleanup)·병합(Merge)하며, 배치 방향에 따라 자동 수정하는 Plug-in
이다. 실무에서 담당자마다 제각각으로 처리하던 벽체 분할·정리 작업을 동일한 규칙으로 자동화해
모델 일관성을 높인다.

## 2. 문제 정의

- 큰 사각형 벽체를 일정 길이 단위로 나누어(예: 층고·개구부 위치 등에 맞춰) 요소를 세분화하는
  작업은 실무에서 반복적으로 발생하지만, 수작업으로 하면 담당자마다 분할 기준이 달라 모델
  일관성이 떨어진다.
- 분할·수정을 반복하다 보면 불필요하게 중복되거나 잘게 쪼개진 벽체 요소·절점이 쌓여 모델이
  지저분해지고, 이를 정리하는 것도 수작업으로는 번거롭다.
- 자막: "이 플러그인은 실무에서 반복되는 벽체 관련 수정 작업을 빠르게 해결하기 위해
  제작되었습니다."

## 3. 목표 사용자

- GEN NX에서 벽체(Wall) 요소를 다루는 구조 모델러·설계자, 특히 여러 담당자가 나누어 모델링해
  벽체 분할 기준이 제각각이 되기 쉬운 협업 프로젝트의 실무자.

## 4. 핵심 컨셉 / 차별점

- **선택→버튼 2단계로 끝나는 극단적 단순함**: "사용 방법은 선택하고 버튼을 누르면 끝"이라는
  캐치프레이즈처럼, ① 벽체 선택 → ② 기능 버튼([벽체 분할] 또는 [벽체 정리]) 클릭 2단계만으로
  전체 작업이 끝난다. 별도 옵션 창이나 복잡한 설정 없음.
- **기준 길이 기반 균일 분할**: "기준 길이(m)·분할 단위" 값 하나로 선택한 사각형 벽체를 동일한
  간격으로 자동 분할 — 담당자마다 다르게 나누던 관행을 하나의 규칙으로 통일.
  영상 예시: 기준 길이 1.0m로 선택 108개 벽체를 분할한 결과 "API 호출: 7회"로 처리 완료.
- **주변 노드 격자 인식 정리**: [벽체 정리] 버튼은 주변 노드 격자에 맞춰 중복되거나 불필요한
  벽체 요소·절점을 자동으로 정리·병합한다 — 단순 삭제가 아니라 격자 정합성을 유지하며 정리.
- **분할·정리·병합 3기능을 한 창에서 순차 사용**: 벽체 분할(1구간) → 불필요한 벽체·절점 정리
  (2구간) → 전체 구조물 벽체 Cleanup 및 최종 확인(3구간)까지 하나의 사이드 패널에서 연속으로
  수행하는 실습 흐름으로 시연됨.

## 5. 워크플로우

### Step 1 — API 연결 및 기준 값 설정

- Wall Helper 패널에서 `MAPI-Key` 입력.
- `기준 길이(m)·분할 단위` 입력(예: 1.0).

### Step 2 — 벽체 분할 (1구간)

- GEN NX 화면에서 분할할 벽체 영역을 선택.
- [벽체 분할] 버튼 클릭 → 기준 길이에 맞춰 벽체를 자동으로 분할.
- 완료 시 "벽체 분할 완료" 팝업에 `대상: GEN 현재 선택 108개`, `API 호출: 7회`가 표시됨 — 즉
  108개 벽체 분할이 내부적으로 7번의 API 호출로 일괄 처리됨(개별 요소당 1회가 아니라 배치
  호출로 최적화된 것으로 추정).
- 이후 GEN NX의 `Query Dialog` 창(Node 조회)으로 분할된 벽체의 절점(Node) 번호(예: 61, 571)를
  직접 조회해 Node·Element 구성이 의도대로 생성됐는지 확인하는 장면이 이어짐 — 결과 검증을
  Plug-in이 아닌 GEN NX 기본 조회 기능으로 하는 점이 특징.

### Step 3 — 불필요한 벽체 및 절점 정리 (2구간)

- 정리·삭제할 벽체 영역을 화면에서 드래그로 지정해 선택.
- [벽체 정리] 버튼 클릭 → "벽체 정리 중..." 진행 표시 후, 주변 노드 격자에 맞춰 중복되거나
  불필요한 벽체 요소 및 절점이 자동으로 삭제·정돈됨.

### Step 4 — 전체 구조물 벽체 Cleanup 및 최종 확인 (3구간)

- 전체 모델링 화면에서 벽체 정리 대상 범위를 다시 드래그로 선택.
- [벽체 정리] 프로세스를 전체 구조물 규모로 재실행 → 노드 및 Wall 요소가 자동으로 삭제·정돈됨.
- ⚠️ 이 구간 진입 직후 패널 하단 상태가 "벽체 병합 완료"로 표시되는 장면이 포착됨 — [벽체 병합]
  버튼을 명시적으로 클릭하는 장면 자체는 프레임 샘플링 간격상 포착되지 않았으나, 분할된 벽체
  일부를 하나로 합치는 병합 단계가 정리 과정 전후로 실행된 것으로 추정됨.
- 정돈된 전체 3D 구조물 모델링을 최종 검토하며 영상 종료.

## 6. 연계 JSON API 엔드포인트

화면에 정확한 요청 바디는 노출되지 않았으나, 결과 팝업에 "API 호출: 7회"라는 문구가 노출되어
이 Plug-in이 GEN NX Open API를 배치 호출 방식으로 사용함이 확인된다. 조작 대상(Wall 요소의
Node/Element 분할·삭제)에 근거해 추정 가능한 엔드포인트:

| 기능 | 추정 API | 문서 위치 |
| --- | --- | --- |
| 벽체 분할(신규 Node·Element 생성) | `POST /db/NODE`, `POST /db/ELEM` | [`03_DB_Node_Element.md#1-dbnode`](../../manual/03_DB_Node_Element.md#1-dbnode), [`#2-dbelem`](../../manual/03_DB_Node_Element.md#2-dbelem) |
| 벽체 정리(중복 Node·Element 삭제) | `DELETE /db/NODE`, `DELETE /db/ELEM` | 위와 동일 |
| 선택 영역 조회 | `GET /view/SELECT` | [`16_VIEW.md#1-viewselect--select`](../../manual/16_VIEW.md#1-viewselect--select) |

- ⚠️ 위 매핑은 화면에 노출된 조작 대상(Wall 요소의 Node/Element)에 근거한 추정이며, 실제 요청
  바디나 정확한 HTTP 메서드 조합(예: PUT을 통한 병합 처리 여부)은 화면에 노출되지 않아 확인되지
  않았다. "API 호출: 7회"라는 수치가 어떤 엔드포인트 조합을 가리키는지도 특정할 수 없다.

## 7. 입력 데이터 규격

- **기준 길이(m)**: 분할 단위(예: 1.0m) — 필수 입력.
- **작업 대상**: GEN NX 화면에서 사용자가 직접 선택한 Wall 요소(사각형 벽체).

## 8. 출력 / 생성 결과

- 기준 길이로 분할된 Wall 요소·Node(벽체 분할).
- 중복/불필요 Wall 요소·Node가 제거된 정돈된 모델(벽체 정리).
- 조각난 벽체 부분이 하나로 합쳐진 모델(벽체 병합).

## 9. 제약사항 및 한계

- 원문 아티클에 소개된 기능은 "벽체 검토" 1건뿐이지만 실제 UI는 분할·정리·병합 3개 버튼으로
  구성되어 있어, 원문 소개 문구가 화면 기능 전체를 세분화해서 설명하지 않은 것으로 보인다(⚠️
  원문과 실제 UI 사이의 설명 깊이 차이 — 오류라기보다는 원문이 상위 개념만 소개한 것으로 판단).
- [벽체 병합] 버튼을 실제로 클릭하는 장면이 프레임 샘플링에서 명확히 포착되지 않아, 병합 기능의
  정확한 동작 조건(어떤 벽체끼리 병합 대상이 되는지)은 확인되지 않았다.
- 대상이 "사각형 벽체"로 한정되는 것으로 보이며(원문: "GEN NX의 사각형 벽체(Wall)"), 비정형
  형상의 벽체에 대한 지원 여부는 확인되지 않았다.
