> 간격으로 프레임 캡처(총 31장) 후 프레임별 육안 분석 + Message Window에 노출되는 GEN NX 해석
> 로그 + 하단 자막을 근거로 작성. 원문 아티클(`docs/plugin_cases/articles/09_RCRebarOptimizer.md`)
> 에 이미 "RC 설계 API(DCRM·CD/BD-ANAL·설계결과표)"라는 표현이 명시되어 있어 API 매핑 근거가
> 처음부터 매우 강했고, Plug-in 화면 내 "최적화 작동 원리" 설명 박스에서도 상세 알고리즘을 직접
> 공개하고 있어 이번 세션에서 가장 정보 밀도가 높은 사례.

## 1. 개요

**RC Rebar Optimizer**는 MIDAS GEN NX의 RC 설계 API(DCRM·CD/BD-ANAL·설계결과표)를 활용해,
RC 기둥·보의 주철근을 후보 규격(D19~D32)으로 자동 스윕 설계하여 검토비(CHK)를 만족하는 부재별
최소 강재 배근을 산출하고, 같은 단면(기둥마크·보마크)을 하나의 표준 배근으로 통일하는 Plug-in
이다.

## 2. 문제 정의

- GEN NX 기본 RC 설계 결과는 부재 하나하나에 대해 이론적으로 필요한 최소 철근량만 계산해줄 뿐,
  실제 시공에서 쓸 표준 규격(예: D19, D22, D25, D29) 중 어떤 걸 몇 개 배근해야 하는지, 또
  비슷한 단면끼리 몇 가지 타입으로 표준화(통일)할지는 설계자가 수작업으로 판단해야 한다.
- 철근 직경별로 전체 부재를 다시 설계해보고 강재량·시공성을 비교하는 과정은 반복 계산이 많아
  수작업으로는 비효율적이다.

## 3. 목표 사용자

- KDS 41 20:2022 기준 RC 기둥·보 배근을 설계·적산해야 하는 구조 설계자.
- 표준화된 배근 타입 수(시공성)와 강재 총중량(경제성) 사이의 trade-off를 판단해야 하는 실무자.

## 4. 핵심 컨셉 / 차별점

- **후보 철근 스윕 → GEN NX 실제 재설계 → 검토비 통과 최소 규격 선택**: "이 도구는 철근을 직접
  계산하지 않습니다. 후보 배근을 하나씩 GEN NX에 입력 → KDS 41 20:2022로 재해석·재설계시키고,
  GEN NX가 검토 통과(CHK OK · 검토비 ≤ 목표)로 인증한 것 중 강재가 가장 적은 배근을 고릅니다.
  즉 최적 탐색 + GEN NX 설계엔진 결합이며, 표시되는 모든 배근은 GEN NX가 실제로 설계·검토한
  값입니다" — 순수 알고리즘 계산이 아니라 GEN NX 자체 설계 엔진을 반복 호출해 검증된 값만
  채택하는 방식임을 UI에 명시. 이 설명 자체가 신뢰성의 핵심 근거로 제시됨.
- **후보 철근 스윕**: 선택한 후보 규격(D19·D22·D25...)마다 전체 기둥/보 주근을 그 규격으로
  설정하고 GEN NX가 재설계, 규격별로 각 기둥의 필요 변수(검토비: 축력 Rat-P, 휨 Rat-M, 전단
  Rat-V)를 얻는다.
- **부재별 최적**: 각 기둥에서 "OK & 검토비 ≤ 목표"인 규격 중 강재가 가장 적은 규격을 강제
  최소로 선택.
- **단면(기둥마크)별 통일**: 같은 기둥마크는 같은 배근을 써야 하므로, 그 마크의 모든 기둥을
  만족시키는 가장 큰 규격으로 통일(가장 불리한 부재에 설계 기준).
- **표준화(자동 추천 + 수동 시공 편의 조정)**: 서로 다른 배근 종류를 N타입 이하로 축소(강재
  증가가 가장 작은 표준부터 순), 각 단면엔 "면적 ≥ 소요량 가장 작은 표준에 배정 → 보수적으로
  검토비 ≤ 1보장". N은 자동 추천되지만 사용자가 타입 수를 직접 클릭해 강재량-타입수 trade-off
  그래프에서 바꿀 수도 있음.
- **적용·재검증**: [모델에 적용] 시 표준 배근을 설계 기준으로서 GEN NX가 재설계·재검토하고, 전
  기둥 검토비 ≤ 1.0임을 실측으로 확인(잠정치는 이때 다르게 재설계될 수 있음도 명시) — 즉
  "예측치"와 "실측치"를 구분하고 반드시 재검증을 거친다.
- **지배요인 진단**: 각 부재의 배근이 왜 그 규격으로 결정됐는지(예: `pmin 지배` = 강도 여유가
  커서 최소철근비(1%)로 배근이 결정된 경우, `P-M 지배` = 축력-모멘트 상관관계가 지배)를 자동
  진단해 표시 — "어느 부재를 더 줄일 수 있는지"까지 제시한다는 원문 3번 기능과 일치.
- **기둥/보 독립 탭 + PDF 산출**: 기둥(Column)/보(Beam) 탭을 분리해 각각 최적화하며, 배근표
  (CSV 다운로드 가능)와 단면별 상세 결과를 즉시 PDF로 출력.

## 5. 워크플로우

### Step 1 — API 연결

- `서버 URL`(예: `https://moa-engineers.midasit.com:443/gen`), `MAPI-Key` 입력 후 "연결 테스트".
- 연결 성공 시 "연결 성공 — 부재 870개 인식. [최적화 실행] 가능합니다" 로 인식된 부재 수를
  즉시 피드백.

### Step 2 — 최적화 설정 (기둥)

- 후보 철근(다중 선택 체크박스): D19, D22, D25, D29, D32.
- 목표 검토비 상한(예: 1.00) 입력.
- "표준 타입 수는 자동 추천됩니다 — 결과의 trade-off 그래프에서 클릭해 바꿀 수 있어요" 안내.

### Step 3 — 최적화 실행 (기둥)

- "최적화 실행" 클릭 → GEN NX Message Window에 실제 해석 로그 순차 출력: `ENTRY
  FORM_STIFF_MASS_LOAD` → `Analysis is in progress`(Forming Element Stiffness and Load
  Matrices → Static Analysis → Eigenvalue Analysis) → `Save Model Data for RC
  Design/Checking` → `Calculate Live Load Reduction Factor` → `Calculate Effective Length
  Factors (Ky & Kz)` → `Start Creating Load Combinations for Design/Checking` → 후보 철근
  직경 개수만큼(예: 4회) `Design Rebar of Concrete Column...`(Stop Design Thread 진행 %) 반복.
- 완료 로그: "완료 — 기둥 40개 / 단면 15층 → 표준 3타입(자동 추천) · 설계기준 완상복원됨".
- 결과 요약 카드 3개: `MIDAS 설계(기준) 3,037.5kg` / `단면별 최적 2,559.4kg(−15.7%)` /
  `표준화(3타입, 추천) 2,729.4kg(−10.1%)`.
- **표준 배근 타입** 카드(예: Type A 6-D19 400×400, Type B 4-2-D29 500×500, Type C 6-D29
  500×600)와 **배근표(Rebar Schedule)**(Type/표준배근/주근 분수/단면 수/기둥 수/주근 총연장/
  강재량) — CSV 다운로드·표 복사 지원.
- **타입 수 ↔ 강재량 trade-off** 막대그래프: 1타입(4,115kg, +60.8%) / 2타입(3,049.9kg,
  +19.2%) / 3타입(2,729.4kg, +6.6%, 현재 선택) / 4타입(2,559.4kg, +0.0%) — 타입 수를 줄일수록
  시공은 편해지지만 강재는 늘어나는 관계를 데이터로 직접 제시.
- **지배요인 진단**: "pmin 지배 13층 / P-M 지배 2층" — pmin 지배는 강도 여유가 커서
  최소철근비(1%)로 배근이 결정됨을 뜻하며, 철근으로는 더 줄이기 어렵고 콘크리트 단면 축소·
  추가 여지가 있음을 시사(구조적으로 재설계된 단면 신중 검토 필요).
- **단면(기둥마크)별 결과** 표: 부재수, 배근(전→후), 검토비(전→후), 주근비(전→후), 지배요인,
  판정(OK). 행을 클릭하면 설계 상세(축력/휨/전단 검토비, 필요 철근량 Ast, 배근 근거, 지배요인
  근거)까지 펼쳐볼 수 있음.

### Step 4 — 최적화 설정·실행 (보)

- 상단 탭을 "보(Beam)"으로 전환 — 기둥과 동일한 UI 원리, 다만 후보가 상/하부 주근 규격(D13~
  D25)과 스터럽 규격(D10·D13·D16) 2축 조합으로 늘어남: "조합 스윕 — (주근 규격 × 스터럽 규격)
  모든 조합을 전체 보를 설계하고 GEN NX가 재설계, 뒤집힐 필요 배근-스터럽 간격-CHK 신속."
- 후보 주근: D13, D16, D19, D22(D25는 "보는 기둥보다 작게" 안내에 따라 제외 상태로 시연).
  후보 스터럽: D10, D13(D16 제외).
- "완료 — 보 175개 / 보마크 75종 → 표준 26타입 · 설계기준 완상복원됨".
- 결과: `기준 설계(기둥) 15,278.1kg` / `부재별 최적 7,951.5kg(−48.0%)` / `보마크 통일(26타입,
  추천) 8,883.3kg(−41.9%)`.
- 표준 보 타입 카드(예: Type A 상 2-D13/하 2-D13 350×600, ... Type I 상 3-D13/하 4-D13
  350×600) 다수(A~Z 이상, 26종) — 각 카드에 스터럽 규격·간격, 보마크수, 보 수까지 표시.
- **배근표(Beam Schedule)**: 상부근/하부근/스터럽/보마크수/보 수/강재량(kg) 컬럼.
- **보마크별 결과** 표: 부재수, 상부근(전→후), 하부근(전→후), 스티럽(전→후), 강재(kg),
  표준타입, 판정. 행을 클릭하면 위치별(I단·중앙·J단) 모멘트 Mu·필요As+상부근·정모멘트
  Mu·필요As+하부근·전단 Vu(LCB)·스터럽·CHK까지 세부 근거가 표시됨.

### Step 5 — 모델에 적용

- "모델에 적용" 클릭 → 표준 배근을 설계 기준(`DCRM`)에 기록하고 GEN NX를 통한 재설계·재검토
  진행(다시 `Analysis is in progress` 진행 상태 창 노출).
- 완료 시: "재검증 완료 — 표준 배근 적용 후 전 기둥 안전: 최대검토비 완상성 0.52 → 표준화 적용
  후 0.52(적용 기둥 40개) — 검토는 여유 있지만 기둥 KDS 검토비 1.0 이하임을 GEN NX 자체설계로
  확인. 적용 후 실제 주근 강재(GEN NX 재설계 실측), 적용 후 기준: 2,729.4kg — 연척기준
  잠정치와 실측으로 확인되었습니다. 표준 취소 → 원 설계기준 복원" 안내와 "적용 취소 — 원
  설계기준 복원" 버튼 제공 — 되돌리기 가능.

### Step 6 — PDF 출력

- "PDF 출력" 클릭 → 인쇄 대화상자(Microsoft Print to PDF)로 단면(기둥마크)별 결과 표(검토비,
  주근비, 지배요인, 판정)와 "부재별 변경 — 전체 기둥 40개 중 40개가 원설계와 다른 배근으로
  통일됨, 변경분 감재 Δ −308.1kg" 요약을 인쇄.

## 7. 입력 데이터 규격

- **후보 철근 규격**(다중 선택): 기둥 D19/D22/D25/D29/D32, 보 주근 D13/D16/D19/D22/D25, 보
  스터럽 D10/D13/D16.
- **목표 검토비 상한**: 예 1.00.
- **선행 조건**: GEN NX 모델에 RC 기둥·보 부재와 KDS 41 20:2022 설계 조건이 이미 정의되어 있어야
  함(연결 시 "부재 870개 인식"으로 자동 파악).

## 8. 출력 / 생성 결과

- 표준화된 기둥/보 배근 타입 카드 및 배근표(CSV).
- 강재량 비교(기준 설계 vs 부재별 최적 vs 표준화) 및 타입 수-강재량 trade-off 데이터.
- 단면(기둥마크)별/보마크별 상세 결과 표(검토비, 지배요인, 설계 근거).
- GEN NX 모델에 반영된 실제 `DCRM-COLUMN`/`DCRM-BEAM` 설계기준(모델에 적용 시).
- PDF 산출물(단면별 결과 표 + 변경 요약).

## 9. 제약사항 및 한계

- 표준화로 절감된 것처럼 보이는 값은 "잠정치"이며, [모델에 적용] 단계에서 GEN NX가 실제로
  재설계·재검토한 뒤에야 "실측치"로 확정된다 — 표준화 화면의 수치를 최종 확정치로 오인하지
  않도록 UI가 스스로 경고.
- pmin 지배 부재는 철근으로 더 줄일 여지가 없고 콘크리트 단면 자체를 줄여야 한다는 점을
  시사하지만, 이 Plug-in은 단면 치수 변경까지는 다루지 않고 진단만 제공.
- 보의 후보 조합은 (주근 규격 × 스터럽 규격)의 전체 조합을 스윕하므로 "큰 모델은 다소 시간이
  걸린다"는 경고가 UI에 명시됨 — 조합 수가 많아질수록 연산 비용이 커지는 구조.
- 원문에 "PDF로 산출해 설계·적산·검토 문서 작성 시간을 크게 단축"한다고 소개되지만, 영상에서는
  기둥 결과만 PDF 출력하는 장면이 확인되고 보 결과의 PDF 출력 장면은 프레임 샘플링에서 명확히
  포착되지 않았다(⚠️ 미확인, 동일 버튼으로 지원될 것으로 추정).
