# AutoWallRebarData 기획문서

> 영상(`docs/plugin_cases/videos/18_AutoWallRebarData.mp4`, 30fps, 1910×1006, 약 169초)을 7초
> 간격으로 프레임 캡처(총 25장) 후 프레임별 육안 분석 + 화면 하단 로그 텍스트를 근거로 작성.
> 원문 아티클(`docs/plugin_cases/articles/18_AutoWallRebarData.md`)의 2대 기능 설명과 교차
> 확인함. GEN NX 네이티브 `Design > Rebar Input > Modify Wall Rebar Data`(Design Input Data)
> 창을 직접 열어 Plug-in이 쓴 결과를 대조 확인하는 장면이 포함되어 있어, 데이터가 정확히 어느
> GEN NX 기능에 대응하는지 명확하다.

## 1. 개요

**Auto Wall RebarData**는 GEN NX 벽체 배근(Modify Wall Rebar Data)을 Wall Mark 또는
두께(Thickness) 기준으로 선택해, 수직·수평·단부보강근·경계요소 철근과 피복·두께를 층 구간별로
한 번에 입력하고, 입력된 배근을 Wall Mark 단위 표로 정리해 PDF로 내보내는 Plug-in이다.

## 2. 문제 정의

- GEN NX 네이티브 `Modify Wall Rebar Data` 기능은 벽체(Wall ID) 단위로 배근을 지정하는데,
  같은 Wall Mark에 속한 여러 층·여러 Wall ID에 동일한 배근을 반복해서 입력해야 하는 경우가
  많아 반복 수작업이 발생한다(원문 1번 기능 "층 반복 수작업을 자동화").
- 입력이 끝난 뒤 벽체 배근 현황을 마크별로 정리한 문서(설계 검토·도서 작성용)를 별도로
  다시 만들어야 하는 번거로움이 있다.

## 3. 목표 사용자

- KDS 41 20:2022 기준 RC 벽체의 수직·수평·단부보강근·경계요소 배근을 입력해야 하는 구조
  설계자.
- 배근 현황을 Wall Mark별 표로 정리해 검토·도서에 활용해야 하는 실무자.

## 4. 핵심 컨셉 / 차별점

- **선택 대상을 Wall Mark 또는 Thickness 2가지 기준으로 전환**: "대상 선택" 섹션에서 Wall
  Mark 탭(체크박스로 CW1, CW2, CW3... 개별/복수 선택) 또는 Thickness 탭(두께 기준 일괄
  선택)으로 전환 가능. Wall ID를 직접 입력(`예: 100-110, 205`처럼 범위·개별 혼합 입력)하는
  것도 지원.
- **층 구간별 배근 다중 정의**: "+층 구간 추가" 버튼으로 여러 개의 층 범위(예: B7~B1,
  1F~15F, 16F~30F)를 만들고, 각 구간마다 독립적인 수직철근/수평철근/피복두께/단부보강근/
  경계요소 규격을 지정 — 실제 설계에서 저층부는 굵은 철근, 상층부는 가는 철근으로 바뀌는
  전형적인 패턴을 그대로 반영.
- **배근 입력 필드 세분화**: 수직철근(규격@간격), 수평철근(규격@간격), 피복두께(내측 DW/외측
  DE, 두께 모벨값 체크), 단부보강근(사용 여부, 규격×개수@간격), 경계수량(간격), 경계길이(mm)
  까지 KDS 41 20 벽체 배근 표준 항목을 모두 커버.
- **적용 전 대상·구간 진행 상태 표시**: "대상 11개 · 구간 1 · 입력완성/미완료" 형태로 몇 개
  Wall ID에 몇 개 층 구간이 정의됐고 입력이 끝났는지 실시간 카운터로 보여줌.
- **로그 창으로 실행 이력 투명 공개**: "연결됨 (HTTP 200)", "총 N개 (미건→선/전체)", "벽체
  선택: 층 그룹 20건", "배근 적용: 완료 N건", "기준 벽체 배근 (REBAR) N건 로드" 등 각 단계의
  API 호출 결과를 로그로 그대로 노출 — 실패 시에도 어느 단계에서 문제가 생겼는지 추적 가능.
- **Wall Mark 단위 배근 리스트 PDF 내보내기**: "현재 모델의 벽체 배근(Wall ID 11개)을 표로
  정리해 인쇄 → PDF로 저장합니다" — 마크별 층 구간·철근·피복·두께 표를 즉시 PDF로 산출.
- **GEN NX 네이티브 기능과 완전히 동일한 데이터 모델 사용**: 적용 결과를 GEN NX 기본 메뉴
  `Design > Rebar Input > Modify Wall Rebar Data`에서 직접 열어보면, Plug-in이 입력한 층
  구간별 배근이 `Wall ID / Wall Mark / Start Story / End Story / Bar` 형태(예: `300-B7`,
  `300-B6`, `300-B5` 처럼 Wall ID에 층 구간 접미사가 붙는 Sub Wall ID 패턴)로 정확히 반영되어
  있어, Plug-in이 GEN NX 네이티브 배근 데이터 구조를 그대로 사용함이 확인됨.

## 5. 워크플로우

### Step 1 — 대상 벽체 확인(GEN NX 네이티브 화면)

- 시연 시작 시 GEN NX `Design > RC Design`(KDS 41 20:2022) 화면에서 대상 모델(70개 층, Wall
  6386개)을 먼저 확인.
- `Design > Design Input Data > Modify Wall Mark Data`에서 CW3 Wall Mark에 이미 여러 Wall
  ID(300, 301, 302, 303...)가 배정되어 있음을 확인 — 이 데이터는 #2/#15의 `/db/WMAK`로 사전에
  구축된 것으로 보임.

### Step 2 — Plug-in 실행 및 API 연결

- `Apps > Plug-in > Auto Wall RebarData` 실행. 실행 전 정보 패널에 "대상: Wall Mark 또는
  Thickness(두께) — 실제 Wall ID란 자동 선별, 없는 ID는 적용 시 스킵", "배근: 수직철근·
  수평철근·단부보강근·경계요소, 피복두께, 층 범위(FROM~TO)별 입력", "철근 호칭 드롭다운, 기존
  배근 자동 채움, 적용 후 자동 재조회" 안내를 확인.
- Base URL/MAPI-Key 입력 → API Settings 팝업에서 Connected 상태 확인.

### Step 3 — 대상 선택

- "대상 선택" 섹션에서 Wall Mark 탭 선택 → CW1(600), CW2(600), CW3(300), CW3(B동)(300),
  CW3A(300)... 목록에서 체크박스로 대상 선택(예: CW3만 선택 → "대상 11개").
- Wall ID 직접입력 필드로 세부 범위 지정도 가능(`300to310`처럼 입력 후 자동 정규화 표시:
  `300 - 310`).

### Step 4 — 배근 입력(층 구간별)

- 층 범위 지정 체크박스 on 시 "전체 층 적용"과 개별 구간 지정 중 선택.
- 첫 구간(예 B7~B1): 수직철근 D13@250, 수평철근 D10@250, 피복두께 DW30/DE50(mm), 단부보강근
  사용 D16×4@100, 경계수량/경계길이는 미사용.
- "+층 구간 추가"로 두 번째 구간(예 1F~15F): 수직철근 D16@150, 수평철근 D13@200(또는 D16@200
  으로 조정)으로 재설정.
- 세 번째 구간(예 16F~30F): 수직철근 D13@150, 수평철근 D13@200으로 상층부에 맞게 축소.
- 철근 호칭은 D4~D57까지 드롭다운으로 선택.

### Step 5 — 배근 적용

- "배근입력하기" 클릭 → 하단 로그에 진행 상황 순차 출력: "연결됨 (HTTP 200)" → "총 70개
  (미건→선) B7→Roof" → "벽체 매핑 도입 1개 완료" → "벽체 선정 층 조 6386개 → Wall(ID 12개),
  두께 그룹 20종" → "기준 벽체 배근(REBAR) 117개 로드".
- "대상 11개 · 구간 3 · 입력완료" 상태로 최종 확인.

### Step 6 — 결과 검증(GEN NX 네이티브 화면 재확인)

- GEN NX `Design > Rebar Input > Modify Wall Rebar Data` 메뉴(네이티브 팝업)를 직접 열어,
  Plug-in이 생성한 층 구간별 Sub Wall ID(`300`, `300-B7`, `300-B6`, `300-B5`, `301`,
  `301-B7`...)가 정확히 등록되어 있음을 확인.

### Step 7 — 배근 리스트 PDF 내보내기

- "PDF/인쇄" 클릭 → "현재 모델의 벽체 배근(Wall ID 11개)을 표로 정리해 인쇄 → PDF로
  저장합니다" 안내에 따라 Wall Mark별 배근 리스트를 PDF로 저장.

## 6. 연계 JSON API 엔드포인트

로그에 명시적인 엔드포인트 이름은 노출되지 않았으나(`GET`/`POST` 성공 여부만 HTTP 200으로
표시), GEN NX 네이티브 `Modify Wall Rebar Data` 창에 정확히 대응되는 데이터가 반영된 것을
직접 확인했다:

| 기능 | 대응 GEN NX 메뉴 | `docs/manual` 커버리지 |
| --- | --- | --- |
| 벽체 배근(수직·수평·단부보강근·경계요소) 조회/입력 | `Design > Rebar Input > Modify Wall Rebar Data` | ⚠️ 전용 엔드포인트 미문서화(아래 참고) |
| Wall Mark 목록 조회 | `Design > Design Input Data > Modify Wall Mark Data` | [`24_DB_Design.md#9-dbwmak--modify-wall-mark-design-벽체-마크-설계-수정`](../../manual/24_DB_Design.md#9-dbwmak--modify-wall-mark-design-벽체-마크-설계-수정) (`/db/WMAK`) |
| Wall Mark별 부재별 철근 설계기준 | (참고) `DESIGN/RC/KDS-41-20-2022/DCRM-WALL` | [`26_Design_RC_KDS41202022.md`](../../manual/26_Design_RC_KDS41202022.md) (§32 `DCRM-WALL`) |

- ⚠️ **중요 발견**: 이 Plug-in이 조작하는 "벽체 배근(Modify Wall Rebar Data)" — 수직/수평
  철근, 단부보강근, 경계요소, 피복두께를 층 구간별로 지정하는 전용 데이터 — 는 `docs/manual`에
  전용 엔드포인트로 문서화되어 있지 않다. §32의 `DCRM-WALL`("벽체 부재별 철근 설계기준")은
  이름은 유사하지만 화면에서 확인한 층 구간별 수직·수평·단부보강근·경계요소 입력 UI와 정확히
  같은 데이터인지는 이 저장소만으로 단정할 수 없다. #5(WallStiffnessAuto)의 `/db/WSSF` 발견과
  마찬가지로, 이 Plug-in도 `docs/manual`의 매뉴얼 커버리지 공백(gap)을 드러내는 사례다 — 정확한
  엔드포인트명은 공식 API 문서에서 별도 확인이 필요하다.
- 배근 리스트 조회(PDF 산출 근거)는 로그의 "기준 벽체 배근(REBAR) 117개 로드" 문구로 보아
  위와 동일한 벽체 배근 엔드포인트를 GET으로 재조회하는 것으로 추정된다.

## 7. 입력 데이터 규격

- **대상 선택**: Wall Mark(복수 체크) 또는 Thickness(두께) 기준, Wall ID 직접입력(범위/개별
  혼합).
- **층 구간별 배근**: 층 범위(From~To), 수직철근(규격@간격), 수평철근(규격@간격), 피복두께
  (내측/외측), 단부보강근(사용 여부, 규격×개수@간격), 경계수량·경계길이.
- **선행 조건**: GEN NX 모델에 Wall Mark(`/db/WMAK`)가 이미 정의되어 있어야 함(대상 선택의
  "Wall Mark" 탭이 이 데이터를 기반으로 동작).

## 8. 출력 / 생성 결과

- GEN NX 모델의 `Modify Wall Rebar Data`에 반영된 층 구간별 벽체 배근(수직·수평·단부보강근·
  경계요소·피복두께).
- Wall Mark 단위로 정리된 벽체 배근 리스트 PDF.

## 9. 제약사항 및 한계

- 실행 전 안내에 "없는 ID는 적용 시 스킵"이라고 명시되어 있어, 대상으로 지정했지만 실제 모델에
  존재하지 않는 Wall ID는 조용히 건너뛴다 — 사용자가 이를 별도로 인지하지 못하면 일부 벽체가
  누락될 수 있다.
- `docs/manual`에 이 Plug-in이 사용하는 벽체 배근 전용 엔드포인트가 문서화되어 있지 않아,
  정확한 요청 스키마(Key/Value)는 이 저장소만으로 확인할 수 없다.
- 층 구간이 서로 겹치는 경우(예: 1F~15F와 10F~20F를 동시에 지정)의 처리 방식은 화면에서
  확인되지 않았다(⚠️ 미확인).
